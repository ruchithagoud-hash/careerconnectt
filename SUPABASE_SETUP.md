## 3. Supabase Client Initialization

The browser/client Supabase client is initialized in:

```
src/integrations/supabase/client.ts
```

This file is auto-generated by Lovable. It creates a `supabase-js` client using:

- `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` in the browser
- `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` fallback for SSR
- Custom fetch handling for the new opaque `sb_publishable_*` API keys
- `localStorage` for session persistence

The server-side admin client (service role, bypasses RLS) is initialized in:

```
src/integrations/supabase/client.server.ts
```

This client is intended for trusted server-side operations only and must be imported dynamically inside server function handlers.

## 4. Authentication Configuration

Authentication is implemented in the following locations:

- **Auth page UI**: `src/routes/auth.tsx`
  - Email/password sign-in
  - Email/password sign-up with link-based email verification
  - Forgot password / password reset
  - LinkedIn OAuth sign-in (UI present; provider must be enabled separately)
  - Sign In | Sign Up segmented tabs

- **Auth state hook**: `src/hooks/use-auth.ts`
  - Subscribes to `supabase.auth.onAuthStateChange`
  - Retrieves the initial session via `supabase.auth.getSession()`
  - Exposes `session`, `user`, and `loading` state

- **Bearer token middleware**: `src/integrations/supabase/auth-attacher.ts`
  - Attaches the Supabase access token to server function calls

- **Start configuration**: `src/start.ts`
  - Registers `attachSupabaseAuth` as `functionMiddleware`
  - Registers a server error middleware

- **Password reset route**: `src/routes/reset-password.tsx`
  - Handles the `PASSWORD_RECOVERY` event from Supabase

| Column | Type | Notes |

## 9. LinkedIn OAuth Future Enablement

LinkedIn OAuth can be enabled on the same Supabase project (`vkdvnlbpgxbgyhgdoabr`) without migrating the backend.

The application code already invokes LinkedIn sign-in via:

```ts
await supabase.auth.signInWithOAuth({
  provider: "linkedin_oidc",
  options: { redirectTo: redirect },
});
```

in `src/routes/auth.tsx`.

### Steps required to enable LinkedIn OAuth later

1. **Create or use an existing LinkedIn Developer application** at the LinkedIn Developer portal.
2. **Configure the LinkedIn OAuth redirect URL** in the LinkedIn Developer app to:
   ```
   https://vkdvnlbpgxbgyhgdoabr.supabase.co/auth/v1/callback
   ```
3. **Enable the LinkedIn OIDC provider in Supabase Auth** for project `vkdvnlbpgxbgyhgdoabr`:
   - Provider: `LinkedIn OIDC`
   - Client ID: from the LinkedIn Developer app
   - Client Secret: from the LinkedIn Developer app
   - Redirect URL: `https://vkdvnlbpgxbgyhgdoabr.supabase.co/auth/v1/callback`
4. **No code changes are required** in `src/routes/auth.tsx` or elsewhere; the existing `handleLinkedIn` function will work once the provider is enabled.
5. **Test the flow** by clicking "Continue with LinkedIn" on the `/auth` page.

Because this project is managed by Lovable Cloud, provider enablement must be performed through the Lovable Cloud backend UI. The Supabase dashboard is not directly accessible for Lovable Cloud projects.
